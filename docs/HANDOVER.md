## 1. ما هو المشروع

منصة تعليم إلكتروني عربية بالكامل (بلا مقر) تخدم الوطن العربي.
حصص مباشرة عبر BigBlueButton، وبرامج قرآن ولغة عربية وتربية إسلامية وبرمجة،
لفئات عمرية من 5 سنوات فما فوق، وأكثر من نصف الطلاب قُصّر.

**تقنيًا:** Laravel واحد بنمط **Modular Monolith** — 27 موديولًا تحت `modules/`،
كل واحد بـnamespace مستقل. PostgreSQL · Redis · Docker Compose ·
Filament للإدارة · Inertia/React لبوابات الطالب والمعلم وولي الأمر.

**الحجم الحالي:** ~80 جدولًا · 61 مسار إدارة · 761 اختبارًا في الجولة الكاملة.

## 3. القواعد الحاكمة — كسرها صامت ومكلف

هذه ليست تفضيلات معمارية. كل واحدة منها قرار عميل صريح:

| القاعدة | التفصيل |
|---------|---------|
| **اعتذار المعلم لا يُلغي الحصة** | الاعتماد يفتح البحث عن بديل فقط. الحصة تبقى بموعدها وحالتها |
| **الحصة لا تفقد معلمها الأصلي** | `original_teacher_id` يُثبَّت عند الإنشاء ولا يتغيّر. `staff_profile_id` هو المعلم **الفعلي** |
| **لا عقوبة آلية على المعلم** | لا تعليق ولا إنهاء ولا تغيير حالة مهما تكرر الاعتذار. القرار يدوي دائمًا |
| **نافذة المخالفات متحركة** | آخر 30 يومًا — **لا** تصفير أول الشهر. القاعدة الشهرية القديمة بطلت |
| **ولي الأمر ممنوع من محادثات الطالب مع المعلم** | حتى لو مرتبطًا به رسميًا. السبب: حماية الطالب من التعنيف |
| **رؤية التسجيلات مغلقة افتراضيًا** | الطالب وولي الأمر لا يريان. الإتاحة بمنحة يدوية لها انتهاء |
| **Sign Up ليس قبولًا** | حساب · طلب · ملف طالب · قيد · عضوية = خمسة كيانات. لا توزيع قبل الاعتماد |
| **لا حذف بيانات بشرية** | تعليق وأرشفة فقط. `SoftDeletes` حد أدنى |
| **دفتر المال append-only** | التصحيح بقيدة تسوية جديدة لا بتعديل |
| **لا أرقام سياسة في الكود** | كلها في `config/`. `if ($count >= 3)` داخل موديول = كسر للعقد |
| **لا نص مكتوب مباشرة في الواجهة** | كل النصوص عبر ملفات الترجمة `{ar,en}` |
| **لا فحص أدوار** | `if ($user->role === 'admin')` ممنوع. Policies و`can:` فقط |

## 4. المنجز في هذه الدفعة

### 4.1 قواعد العمل والوثائق

`docs/client-answers.md` اكتسب قسم `CLIENT UPDATE — 2026-08-22` وهو المرجع المُلزِم.
`config/admission.php` **ملف جديد** يحمل قواعد القبول والأهلية والمطابقة واسم المستخدم.
`config/discipline.php` و`config/recordings.php` و`config/scheduling.php` صُحِّحت لتطابق القواعد الجديدة،
والقيم التي بطلت مُعلَّمة صراحةً في التعليقات.

### 4.2 الحصص والمدرس البديل

- `original_teacher_id` على `sessions` — يُثبَّت في الموديل عبر `creating` hook، ويُمنع تغييره عبر `updating` hook.
  **لماذا لا يوجد `actual_teacher_id` منفصل:** قيد منع الحجز المزدوج مبنيّ على `staff_profile_id`،
  وهذا صحيح لأن التعارض يخصّ من يقف في الفصل فعلًا. الموديل يكشف المعنى عبر `actualTeacherId()`.
- `session_substitutions` — سجل دائم لكل استبدال يصمد أمام استبدالات متتالية.
- `teacher_apologies` + `ApologyStatus` + `SubmitTeacherApologyAction` + `DecideTeacherApologyAction`.
- `ApologyEscalationEvaluator` — سُلَّم متابعة بنافذة متحركة من الإعدادات.

**الاختبارات:** 7 ناجحة · 23 توكيدًا. تثبت أن الاعتماد لا يُلغي الحصة، وأن اعتذارًا
عمره 31 يومًا لا يُحتسب (وهو ما يميّز المتحركة عن الشهرية).

### 4.3 الإشعارات (منفَّذة بواسطة Codex)

قنوات ثلاث عبر الصندوق الصادر الموجود: In-App · Email عبر Laravel Mail (مستقل عن المزوّد) ·
WhatsApp Cloud API بقوالب معتمدة. تطبيع أرقام إلى E.164 · قوالب متعددة اللغات مع سقوط
لغوي · تمييز الفشل القابل لإعادة المحاولة · إعادة إرسال يدوي محكومة بصلاحية.

**قاعدة محفوظة ومختبَرة:** فشل القناة لا يُفشل العملية الأصلية.

**الاختبارات:** 86 ناجحة · 433 توكيدًا · تحقق يدوي عبر Mailpit.

### 4.4 الأمن والخصوصية

- **توحيد أسماء الصلاحيات** — كانت الـPolicies تفحص `students.view_any` والقاعدة تحمل
  `student.view`، فكانت `can()` ترجع `false` دائمًا و**لوحة الإدارة ترجع 403 على كل مورد**.
  هذا كان العائق رقم واحد في المشروع كله.
- **حظر ولي الأمر من محادثات الطالب** — مع إزالة اشتقاق صلاحياته من `guardian_links` داخل Messaging.
- صلاحيات جديدة: `classroom.observe` · `classroom.moderate` · `recording.view.any` ·
  `recording.grant` · `classroom.guest.invite` · `classroom.guest.revoke`.

**الاختبارات:** ولي أمر يملك `guardian.view` يطلب المحادثة عبر HTTP → **403**.
مشرف يملك `message.moderate` → يمر.

### 4.5 الطلاب والجغرافيا والأكاديمي

- `countries` و`regions` — 22 دولة عربية و27 محافظة مصرية، من ملف بيانات لا من كود.
- `registration_applications` بسبع حالات + `StudentAdmissionQueries::isClearedForAssignment`.
- `teacher_courses` + `TeacherQualificationQueries` — أساس ترشيح البديل.
- `UsernameSuggester` — بادئة من إعدادات المؤسسة، وتحويل الاسم العربي إلى لاتيني.
- `program_categories` بمفتاح أب ذاتي + `course_category` — كورس في أكثر من تصنيف.
- `program_eligibility` + `EligibilityEvaluator` — دول ومناطق وعمر وجنس، والقوائم الفارغة
  تعني «بلا قيد». قاعدة تطابق الجنس **إعداد برنامج** لا شرط باسم برنامج.

### 4.6 واجهة الإدارة

**اللوحة كانت معطّلة بالكامل** — الويدجتات والنماذج والجداول فارغة. السبب: Livewire يبدأ
Alpine قبل تنفيذ باقي سكربتات Filament فتفوت مستمعاتها `alpine:init`.
الشيم يعيد إطلاق الحدث بعد جاهزية Livewire ثم يعيد تهيئة الشجرة.

45 موردًا تخلّى عن النص العربي المكتوب داخل الكود إلى مفاتيح ترجمة.
موارد كانت موجودة بلا مسارات لغياب `getPages()` صارت قابلة للوصول.

## 5. حالة المرحلة الأولى

**المرحلة الأولى غير مكتملة.** الأربع مناطق:

| المنطقة | الحالة |
|---------|--------|
| A الطلاب والمعلمون والتسجيل | **Partial** — البنية والعقود نزلت، الشاشات ناقصة |
| B البرامج والكورسات والمجموعات | **Partial** — الهيكل والأهلية نزلا، التحقق اليدوي لم يتم |
| C الحصص والجدولة والبديل وBBB | **Partial** — الاعتذار والأصلي/الفعلي تمّا، الباقي مفتوح |
| D الإشعارات | **Implemented** — بحدود معروفة |

### الناقص الأبرز

- **إتاحة المعلم والطالب** والخانات المتوافقة — لم تبدأ (الحزمة C).
- **منع تعارض الطالب والمجموعة** — قيد المعلم فقط موجود.
- **دخول BBB الديناميكي** ودخول الإدارة والمشرف ودعوة الضيف الآمنة.
- **معالجة أحداث الدخول والخروج** ومؤشرات الحضور والتزام المعلم بالمدة.
- **منح الوصول للتسجيلات** (`recording_access_grants`).
- **مهلة تقرير الحصة** وعقد طلب تغيير المعلم.
- **بروفيل الطالب والمعلم العمليان** — صفحات عرض لا بروفيلات.
- **السيناريوهات الاثنا عشر** — لم يُكتب أي منها.

## 7. درس التشغيل الأهم — منهج التحقق

خلال هذه الدفعة عمل **خمسة منفّذين متوازين**. أُعلن اكتمال بنود **ثلاث مرات** ثم
تبيّن بالفحص أنها غير مكتملة:

| الادعاء | الواقع عند الفحص |
|---------|------------------|
| «اختبارات التفويض أُنشئت» | 3 اختبارات تسقط بـ`Call to undefined method` — صفر توكيد نُفِّذ |
| «إدارة الحصص واختيار البديل جاهزان» | `SessionResource` بلا `getPages()` — **صفر مسار**، الشاشة غير قابلة للوصول |
| «الحزمة A مكتملة» | ثلاثة ملفات أحداث بـ`implements` على كلاس abstract — **التطبيق ساقط بالكامل** |

**القاعدة المستخلصة، طبّقها حرفيًا:**

> لا تُسجَّل حالة بناءً على تقرير منفّذ. أعد تشغيل الاختبار بنفسك، وافتح الشاشة
> في المتصفح بنفسك، وشغّل `route:list` بعد كل حزمة.

`docs/phase-1-critical-modules.md` يحمل قسم **«سجل التحقق — ما أثبته مدير المشروع
بنفسه»** — كل سطر فيه أُعيد تشغيله أو فُتح في المتصفح.

**فحص التكامل في ثانيتين** — شغّله بعد كل دفعة:
```bash
docker compose exec -T app php artisan route:list --path=admin
```
لو رمى خطأ فالتطبيق ساقط. هذا الأمر كان سيمسك عطلين من الثلاثة أعلاه فورًا.

## 8. البيئة والتشغيل

**PHP على جهاز المطوّر الحالي 5.6 — كل أوامر PHP داخل Docker:**

```bash
docker compose up -d
docker compose exec -T app php artisan migrate --force
docker compose exec -T app php artisan test --filter=<Name>
docker compose exec -T app vendor/bin/pint
docker compose exec -T app vendor/bin/phpstan analyse --memory-limit=1G
docker compose exec -T postgres psql -U eschool -d eschool -c "\d <table>"
```

- اللوحة: `http://localhost:8090/admin` — `admin@eschool.test` / `password`
- البريد التجريبي: `http://localhost:8025` (Mailpit)
- حساب الأدمن يحتاج دور `platform_admin`: `php artisan eschool:admin --email=... --password=...`

**تشغيل الاختبارات بالتوازي بلا تعارض:** انسخ `phpunit.xml` وغيّر `DB_DATABASE`،
وأنشئ القاعدة أولًا. (`phpunit.agent-*.xml` أمثلة موجودة، وهي مستثناة من git.)

**فخّ معروف:** `RefreshDatabaseState::$migrated` عام على مستوى العملية. أي trait
يحصر `migrate:fresh` بـ`--path` سيجعل كل كلاس اختبار لاحق يتخطى الهجرة ويجد قاعدة
ناقصة الجداول. حدث هذا فعلًا في `RefreshAuditDatabase` وصُحِّح.

## 9. الخطوة التالية الموصى بها

3. **اكتب السيناريوهات الاثني عشر** — `docs/agent-tasks/AGENT-G-scenario-tests.md`.
   هي بوابة القبول الحقيقية للمرحلة الأولى.
4. **صفِّ الـ75 اختبارًا الفاشلة** بدءًا من factories المشتركة لـSessions/Programs، ثم صلاحيات Assessments وبقية HTTP — `docs/agent-tasks/AGENT-H-test-repair.md`.
5. **اختبر BBB بـcredentials حقيقية** قبل أي وعد للعميل.

**السيناريو الذي يقيس النجاح فعلًا:**

> استقبال طلب طالب → مراجعته → قبوله → توزيعه → اختيار مدرس مناسب →
> إيجاد موعد متوافق → إنشاء الحصص → إخطار الأطراف عبر المنصة والبريد والواتساب →
> دخول المدرس والطالب للفصل → دخول المشرف → إضافة ضيف بأمان →
> استبدال المدرس عند الاعتذار **دون إلغاء الحصة** → حفظ تاريخ الأصلي والمنفِّذ →
> تسجيل أحداث الدخول والخروج → تسجيل الحصة → تطبيق صلاحيات التسجيل.

إذا عمل هذا من الواجهة حتى قاعدة البيانات والتكاملات، فالمرحلة الأولى قريبة فعلًا.

## 10. ملاحظة ختامية

هذا المشروع بُني بمنفّذين متوازين تحت إشراف مركزي. النمط نجح في السرعة وفشل
مرارًا في **صدق التقارير**. القيمة الحقيقية لم تكن في كتابة الكود — بل في رفض
قبوله دون إثبات.

سلّمه كما استلمته: **بحالات صادقة، لا بادعاءات مريحة.**
