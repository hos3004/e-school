# انتقال لوحة الإدارة إلى النسخة الجديدة

طلب المستخدم نشر التحديث الكامل على school-web وجعل اللوحة الجديدة أساسية، مع الاحتفاظ بلوحة Filament القديمة كرابطv2.

## التوجيه

- CONSOLE_ENABLED=true يشغّل الصفحات الجديدة.
- CONSOLE_PRIMARY=true يفعّل التحويل الأساسي مع الحفاظ على id لوحة Filament باسمadmin وصلاحياتها الحالية.
- /manage هو عنوان اللوحة الجديدة، و/admin مدخل متوافق إليها.
- /v2 عنوان اللوحة القديمة، مع رابط مباشر داخل تنقل اللوحة الجديدة.
- أسماء مسارات Filament لا تتغير؛ الروابط التفصيلية القديمة تُحفظ عبر تحويلGET.
- الطلاب والمعلمون يستخدمون /learn وفق ملفهم وصلاحياتهم؛ مسارات الكتابة ودخول الحصص تبقى صالحة.

## حزمة النشر

تُنقل نسخةGit مثبتة وأصولVite المبنية فقط. لا تُنقل قاعدة المعاينة أو.env أو ملفات الاختبار المحلية. تُحفظ ملفات التشغيل الخاصة بالسيرفر غير المتتبعة. Composer.lock لم يتغير عن أساس الإنتاج.

## خطوات التشغيل

1. التأكد من أن رأسschool-web هو الأساس المتوقع وعدم وجود تعديلات كود جديدة.
2. نسخة احتياطية محمية للكود والأصول و.env والتخزين وقاعدةPostgreSQL، مع تجربة استعادة إلى قاعدة مؤقتة مستقلة.
3. صيانة قصيرة وإيقاف عمال المهام والجدولة خلال التحويل.
4. دمجfast-forward لحزمةGit، ونقل الأصول المبنية مع إبقاء الأصول السابقة للطلبات المفتوحة.
5. تشغيل الهجرة الجديدة:2026_09_06_120000_add_offering_to_registration_forms. هي إضافيةnullable ولا تنقل أو تحذف طلبات قديمة.
6. ضبط علمَيConsole وقرصContent المحلي الخاص، دون تعديل أسرار أو إعدادات تكاملات الإنتاج.
7. تجديدautoload وconfig/routes/views وإعادة تشغيلPHP والعمال والجدولة.
8. فحصGET للواجهات الأساسية والقديمة، والتحقق من ثبات أعداد السجلات الأساسية والدفاتر.

## الرجوع

المسار الأسرع تعطيلCONSOLE_PRIMARY ثمCONSOLE_ENABLED وتجديدconfig/routes وإعادةPHP والعمال. تبقى الأعمدة الجديدة والبيانات المدخلة محفوظة؛ لا يُستخدمmigrate:rollback لهذا الانتقال. النسخة الاحتياطية السابقة متاحة لاسترجاع الكود والأصول عند الحاجة، ولا تُستعاد قاعدة قديمة فوق بيانات أحدث دون قرار منفصل.
