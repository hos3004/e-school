# مركز التجهيز ومسار القرآن الفردي — تنفيذ Console v2

> وثيقة نقطة التسليم الأولى. تحديث القرآن الكامل ونتائج QA اللاحقة في [console-quran-demo-parity.md](console-quran-demo-parity.md)، وتقويم الحصص في [console-sessions-implementation.md](console-sessions-implementation.md). أرقام الاختبارات أدناه تاريخية لهذه النقطة.

هذه الصفحات تعمل على التطبيق وخدماته الحالية داخل نسخة Console v2 المعزولة. لا تتضمن بيانات النموذج التصميمي ولا تنشر تغييرات في السيرفر.

## مركز الكورسات والمجموعات

- `GET /manage/courses`: الكورسات، يتطلب `course.manage`.
- `GET /manage/courses/programs`: البرامج والمستويات، يتطلب `program.manage`.
- `GET /manage/groups`: تبويب المجموعات مباشرة، يتطلب `group.view`.
- POST/PATCH على `/manage/courses/{programs|levels|items}` والمعرّف عند التعديل، مع صلاحية المورد.
- POST/PATCH على `/manage/groups` والمعرّف عند التعديل؛ POST `/manage/groups/{group}/teachers` و`/activate` تتطلب `group.manage`.

طلبات الحفظ تمرر قائمة حقول محددة لكل نوع إلى الإجراء؛ لا يصل وصف النموذج المشترك إلى المستوى ولا ترتيب الظهور إلى الكورس. الاختبار الصارم أعاد فشل المستوى أولًا ثم نجح بعد هذا التقييد، دون تعديل fillable أو قواعد الإجراءات.

كل ذلك يقع داخل middleware اللوحة: تسجيل الدخول، `admin.panel.access`، وتفعيل `console.enabled`.

واجهتا الخدمات داخل Academics وGroups تعيدان arrays وتستقبلان معرفات. نماذج الموديول تبقى داخله، والكتابة تستدعي الـ Actions الحالية مع Policies وعزل المؤسسة. لا إنشاء تلقائي لبرنامج أو مستوى. إنشاء المجموعة وربط برامجها في معاملة واحدة، وتأهيل المعلم وربط الكورس ببرنامج المجموعة يفحصان على الخادم. السعة وتاريخ البداية يظلان اختياريين للمسودة، ثم تُطبق شروط التفعيل الحالية.

المحرر يعرض اسمًا عربيًا واحدًا ووصفًا عربيًا واحدًا، مع المدة والجمهور وأسعار البرنامج الأساسية. تحديث العربية يحافظ على ترجمات الإنجليزية والفرنسية القديمة دون إظهارها أو مسحها. حقول شروط القبول والتصنيفات والمتطلبات وقواعد الإكمال لا تُرسل ضمن التعديل ولا تُمسح. نقل محرراتها الكاملة يظل ضمن أعمال الانتقال؛ الإمكانات الحالية لم تُحذف.

قائمة الكورسات والمجموعات تستخدم جدولًا داخل لوحة واحدة وتبويبات خفيفة وأدوات بحث وترشيح. الكورسات تُظهر البيانات المحسوبة المتاحة فقط؛ لا توجد أعداد طلاب أو مجموعات مفترضة. نماذج التجهيز صفحات بتقسيم التصميم المعتمد، حقول موحدة وملخص جانبي. يمكن إنشاء البرنامج والمستوى من داخل نموذج الكورس؛ تبقى مسودة الكورس محفوظة ويُختار المعرّف الذي أعاده الخادم بعد نجاح الحفظ.

إدخال السعر وعرضه بوحدة العملة المعتادة. محول ConsoleMoney الخاص باللوحة يستخدم بيانات ICU لدقة العملة، وعمليات نصية صحيحة دون float أو تقريب صامت، ثم Money::of للقيمة المخزنة. على سبيل المثال 100.50 EGP تُخزن 10050، وJPY دون كسور، وKWD حتى 3 منازل. لا تعديل لـ Money العام أو APIs الأصلية أو دفاتر الحسابات.

## القرآن الفردي

- `GET /manage/quran`: يتطلب `student.view.any`، مع ترشيح pending/assigned/all وبحث وصفحات.
- `POST /manage/quran/{student}`: يتطلب `student.view.any` و`schedule.manage`.
- `GET /manage/quran/availability`: الصلاحيتان نفسهما؛ staff_profile_id وweekdays وduration_minutes وinterval_weeks وtimezone وstarts_on وends_on.
- الاستجابة للإتاحة: available_start_times وhas_declared_availability، مصدرها خدمة الجدولة الحالية.

يستدعي الحفظ `BulkCreateIndividualQuranSchedulesAction::executeSingle` دون تغيير الإجراء أو صفحة Filament. تُقرأ إعدادات المدد والفاصل من config، وتوقيت البداية الافتراضي من إعداد المؤسسة المركزي. لا organization_id أو actor_id من العميل. سبب التدقيق هو `students::admin.individual_quran.placement_audit_reason` نفسه المستخدم حاليًا.

كل صف يحفظ عبر طلب JSON مستقل ويحافظ على مسودات الصفوف الأخرى. تعرض الأيام والوقت المختلف لكل يوم والمدة والتكرار والمنطقة الزمنية وتاريخ البداية والنهاية قبل الحفظ وبعده. الجدول المحفوظ للقراءة، مع رابط واضح إلى محرر الجدولة الحالي للمستخدم المخوّل؛ نقل محرر الجدولة الكامل إلى الثيم الجديد عمل منفصل عن تسكين الطالب الجديد.
