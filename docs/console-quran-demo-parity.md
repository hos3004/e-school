## التحقق

- 113 اختبارًا ناجحًا، 2986 assertion: ConsoleQuranTest وConsoleRegistrationTest وSchedulingOperationsTest وModuleBoundariesTest.
- سجل التشغيل: storage/logs/console-quran-demo-tests.log.
- الاختبارات عبر Docker وscripts/test-isolated.php، بقاعدة وملفات مستقلة لكل تشغيل.
- PHPStan الموجه وPint وفحص TypeScript وESLint ناجحة.
- اختبارات تعديل أوقات مختلفة مع Africa/Cairo، المحافظة على الحضور والحصص الماضية والمحميّة، rollback عند التعارض، عزل المؤسسة وصلاحيات القراءة/الحفظ، وحالة الحساب والملف.
- قبول طلب جديد ثم تعارض لا يترك قيدًا أو جدولًا جزئيًا. الطلب المختار وحده ينتقل إلى Assigned؛ تكرار الحفظ لا يضاعف القيد.
- تدقيق Chrome على المعاينة: إنشاء الأحد14:00 والأربعاء16:00 ثم تعديل الأربعاء17:00 مع بقاء الأحد14:00. إنشاء نافذة إتاحة الاثنين10:00–12:00 ثم اعتمادها فعليًا.
- عرض هاتف فعلي375×812: scrollWidth365 دون تمدد الصفحة؛ الجدول يتمرر داخليًا، محرر375px وحقول44px. تمت استعادة viewport بعد الفحص.
- شاشة الدخول المعاينة أظهرت الهوية بعمودين ومدخلي الطالب والمعلم وإظهار كلمة المرور.

## حدود قواعد العمل القائمة

- الإتاحة المعتمدة لا تُعدّل ولا تُحذف بإجراءات Staff الحالية؛ الواجهة تظهر هذا صراحة، وتتيح إنشاء نافذة جديدة ومراجعة المعلّقة. لم نتجاوز Policy أو الحالات النهائية.
- ملخص الحضور والتقدم مربوط بالفترة المختارة؛ لا توجد أرقام توضيحية، ولا تتسرب ملاحظات المشرف الخاصة.
- تكييف محرر الإتاحة لبوابة المعلم بنفس الخدمة تحت ملكية وكيل البوابات، دون تكرار المنطق.
- تقويم الحصص وإدارة الجداول الجماعية أصبحا متاحين ضمن الدفعة نفسها؛ توثيقهما في console-sessions-implementation.md ولا يغيّران هذه الجداول الفردية.

## تكامل الخدمات

PlaceConsoleQuranStudentAction في جذر التطبيق ينسق عقود القبول والأهلية والقيد وإجراء الجدولة. ConsoleQuranRegistrationService يبقي نماذج الطلبات داخل Students. executeSingle في الإجراء الأصلي أضيف له applicationId اختياري بقيمة null الافتراضية لتحديث الطلب الصحيح دون تغيير عمل العملاء القديمة. استعلامات القرآن تُرجع DTOs أو مصفوفات فقط ولا تعبر بواجهات Eloquent بين الموديولات.
