# 21 — تعريف الإنجاز

**لا يقول أي وكيل "خلصت" قبل أن تتحقق كل بنود القائمة المناسبة.**

الغرض من هذه الوثيقة أن يُنتج عشرة وكلاء يعملون بالتوازي **مستوى جودة واحدًا**،
لا عشرة مستويات.

---

## القائمة الأساسية — لكل مهمة بلا استثناء

### الكود

- [ ] `declare(strict_types=1);` في كل ملف PHP جديد
- [ ] `composer lint` يمر بلا أخطاء
- [ ] `composer stan` يمر عند المستوى 6 بلا تجاهلات جديدة
- [ ] لا `TODO` ولا `FIXME` ولا كود معلَّق متروك
- [ ] لا `dd()` ولا `dump()` ولا `var_dump()`
- [ ] كل دالة عامة لها أنواع معلَنة للمعاملات والمُرجَع

### الحدود المعمارية

- [ ] لا استيراد لنموذج من موديول آخر
- [ ] التواصل عبر Event أو Contract أو Query Service فقط
- [ ] الموديول يكتب في جداوله فقط
- [ ] `composer test:arch` يمر

### قواعد العمل

- [ ] **لا رقم سياسة مكتوب في الكود** — كله من `config/` أو الإعدادات
- [ ] الحالات `enum` وليست نصوصًا
- [ ] كل انتقال حالة يمر بـ `canTransitionTo()`
- [ ] الحراس المذكورة في `05-state-machines.md` مُنفَّذة ومُختبرة

### قاعدة البيانات

- [ ] الهجرة في مجلد الموديول لا في الجذر
- [ ] كل الفهارس المذكورة في `07-database-schema.md` موجودة
- [ ] كل مفتاح أجنبي يعلن `ON DELETE` صراحةً
- [ ] `organization_id` موجود في أي جدول تشغيلي
- [ ] `SoftDeletes` على الجداول البشرية · **لا** على الجداول المالية
- [ ] الهجرة قابلة للتراجع (`down()` تعمل فعلًا)

### الصلاحيات

- [ ] Policy لكل مورد جديد، مسجَّلة في مزوّد خدمة الموديول
- [ ] كل مسار محمي بـ `can:` أو `authorize()`
- [ ] الصلاحيات الجديدة مضافة في `06-permissions-matrix.md` **و** في الـ seeder
- [ ] **لا** فحص على اسم الدور في أي مكان

### التحقق من المدخلات

- [ ] FormRequest لكل عملية كتابة — لا تحقق داخل المتحكم
- [ ] رسائل الخطأ من ملفات الترجمة، لا نصوص مباشرة
- [ ] الحقول الحساسة تتطلب `reason` نصيًا إلزاميًا

### التوطين

- [ ] **لا نص مكتوب مباشرة** في واجهة أو إشعار أو استثناء يراه المستخدم
- [ ] مفاتيح الترجمة موجودة في `ar` **و** `en`
- [ ] الواجهة مختبرة في وضع RTL
- [ ] التواريخ تُخزَّن UTC وتُعرض بتوقيت المستخدم

### التدقيق

- [ ] كل تغيير على الحضور أو الحالة الأكاديمية أو المال أو الصلاحيات
      يترك سطرًا في `audit_log`
- [ ] السطر يحمل: الفاعل · القيمة قبل · القيمة بعد · السبب

### الاختبارات

- [ ] اختبار وحدة لكل قاعدة عمل ولكل انتقال حالة
- [ ] اختبار وظيفي للمسار السعيد ولمسار الرفض بالصلاحيات
- [ ] الاختبارات تمر محليًا وفي CI
- [ ] تغطية الموديول لا تقل عن **70%**
- [ ] الاختبار يفشل لو حُذفت القاعدة التي يحرسها

### التوثيق

- [ ] الوثيقة المعنية محدَّثة لو تغيّر سلوك
- [ ] أي انحراف عن الخطة مسجَّل في `18-ADRs.md`
- [ ] `README` الموديول يشرح: ماذا يملك · ماذا ينشر · على ماذا يعتمد

## قوائم إضافية حسب نوع العمل

### موديول جديد

- [ ] `<Name>ServiceProvider` يرث `BaseModuleServiceProvider`
- [ ] مُسجَّل في `config/modules.php` بالطبقة الصحيحة
- [ ] `routes/web.php` و `routes/api.php` موجودان ولو فارغين
- [ ] ملفات الترجمة `ar` و `en` موجودة
- [ ] Factories و Seeder للبيانات التجريبية
- [ ] `README.md` بالبنية المطلوبة أعلاه

### عملية مالية

- [ ] القيدة تحمل `rate_snapshot` كاملًا
- [ ] لا مسار يعدّل أو يحذف قيدة قائمة
- [ ] `UNIQUE` يمنع القيدة المكررة
- [ ] الفترة المقفلة ترفض القيد الجديد
- [ ] العملة موحدة والحساب بأعداد صحيحة — **لا `float`**
- [ ] الأمثلة الثلاثة في `14-payroll-rules.md` تعطي أرقامها بالضبط
- [ ] إعادة تشغيل المهمة مرتين لا تضاعف شيئًا

### تكامل خارجي

- [ ] خلف واجهة في `Domain/Contracts` — لا استدعاء مباشر
- [ ] تنفيذ `Null` للاختبارات
- [ ] مهلة زمنية + إعادة محاولة + قاطع دائرة
- [ ] الأخطاء تُترجم لاستثناء المجال
- [ ] الأسرار من `.env` — لا قيمة مكتوبة في الكود
- [ ] `healthCheck()` منفَّذ ومربوط بلوحة الحالة

### واجهة مستخدم

- [ ] تعمل على 375 بكسل عرضًا وما فوق
- [ ] تعمل في RTL و LTR
- [ ] حالات: تحميل · فارغ · خطأ · نجاح — كلها مصممة
- [ ] لوحة المفاتيح تصل لكل عنصر تفاعلي
- [ ] تباين الألوان يحقق WCAG 2.2 AA
- [ ] لا استدعاء API في حلقة عرض

### إشعار جديد

- [ ] مسجَّل في `config/notifications.php` بفئته
- [ ] القالب موجود بـ `ar` و `en`
- [ ] يمر عبر Outbox — لا إرسال مباشر
- [ ] `idempotency_key` يمنع التكرار
- [ ] يحترم تفضيلات المستلم وساعات الهدوء
- [ ] قالب واتساب معتمد لو كانت القناة مفعّلة

---

## بوابة المراجعة

قبل دمج أي فرع:

1. `composer check` يمر كاملًا (lint + stan + test).
2. اختبارات المعمارية تمر.
3. الهجرات تعمل على قاعدة نظيفة **وعلى قاعدة فيها بيانات**.
4. `php artisan migrate:rollback` يعمل بلا أخطاء.
5. الرحلة المتأثرة مُجرَّبة يدويًا مرة واحدة على الأقل.
6. `docs/PROGRESS.md` محدَّث.

## علامات الرفض الفوري

أي واحدة من هذه تعني إعادة العمل، بلا نقاش:

| العلامة | لماذا |
|---------|-------|
| رقم سياسة داخل الكود | يجعل تغيير السياسة نشرًا برمجيًا |
| فحص على اسم الدور | يكسر نظام الصلاحيات كله |
| نص ظاهر بلا ترجمة | يمنع دعم لغتين |
| استيراد نموذج عبر الحدود | يحوّل المشروع لكتلة واحدة |
| تعديل أو حذف قيدة مالية | يفقد سلامة الدفتر |
| `float` في حساب مالي | أخطاء تقريب في المال |
| تغيير حالة بلا آلة حالات | يفتح انتقالات غير صالحة |
| حذف نهائي لبيانات إنسان | مخالف لقرار العميل الصريح |
| اختبار لا يفشل عند حذف القاعدة | اختبار زائف |
