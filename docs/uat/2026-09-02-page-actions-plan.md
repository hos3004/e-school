## 1. الاكتشاف الأهم: المشكلة ليست أزرارًا ناقصة

عند تتبّع كل `Action` مكتوب في `Application/Actions` ومَن يستدعيه، ظهر أن
**إجراءات إدارية مكتملة ومختبَرة لا يصل إليها المستخدم من اللوحة إطلاقًا**.
مكتوبة، ولها سياسات وصلاحيات، ومربوطة بمسار HTTP — وبلا زر واحد:

| الإجراء | ما يفعله | حالته |
|---|---|---|
| `Discipline\DecideReactivationAction` | البتّ في طلب فك التجميد | **لا زر** |
| `Discipline\WaiveViolationAction` | إسقاط مخالفة | **لا زر** |
| `Discipline\CancelReactivationAction` | إلغاء الطلب | **لا زر** |
| `Certificates\AwardBadgeAction` | منح شارة لطالب | **لا زر** |
| `Certificates\IssueCertificateAction` · `RevokeCertificateAction` | إصدار/سحب شهادة | **لا زر** |
| `Integrations\RequeueDeadDeliveryAction` | إعادة إدراج webhook فاشل | **لا زر** |
| `Payroll\ReleaseDeferredEntriesAction` | تحرير المستحقات المؤجَّلة | **لا زر** |
| `Payroll\Propose/Approve/RejectPayrollAdjustmentAction` | دورة التسويات المالية | **لا زر** |
| `Reporting\RecordOrganizationSnapshotAction` | التقاط لقطة المؤسسة | **لا زر** |
| `Reporting\CorrectStudentDashboardAction` | تصحيح لوحة طالب | **لا زر** |
| `Messaging\FlagMessageAction` | تعليم رسالة للمراجعة | **لا زر** |
| `Audit\PruneExpiredEntriesAction` | تنظيف قيود التدقيق المنتهية | **لا مستدعٍ إطلاقًا** |

أخطرها **البتّ في طلبات فك التجميد**: الطالب المجمَّد يقدّم طلبًا، والطلب يصل،
ولا يملك المشرف طريقًا في اللوحة لقبوله أو رفضه. لوحة المعلومات نفسها تعرض
«طلبات فك تجميد معلّقة: 1» — تنبيهٌ إلى بندٍ لا سبيل لإغلاقه.

فالخلل ليس تجميليًا: **وظائف مدفوعة الثمن معطّلة خلف واجهة صامتة.**

## 2. النمط الموحد

ثلاث طبقات، تُطبَّق من `table()` وحدها بسطر واحد لكل مورد فلا تُلمس صفحات
Filament ولا تُنشأ أصناف صفحات جديدة:

```php
public static function table(Table $table): Table
{
    return RecordOriginGuide::for($table, 'discipline::origin.reactivation')
        ->columns([...])   // بقية السلسلة كما هي
}
```

`Shared\Filament\RecordOriginGuide` يضبط ثلاثة أشياء:

1. **`emptyStateHeading` + `emptyStateDescription`** — من أين تأتي هذه السجلات.
2. **`emptyStateActions`** — زر ينقل إلى مصدرها الحقيقي.
3. **`headerActions`** — الزر الأساسي حين يوجد إجراء فعلي (الفئة أ).

النصوص كلها في ملفات ترجمة الموديولات تحت مفتاح `origin.*` — لا نص في الكود،
التزامًا بالبند 8 من `CLAUDE.md`.

المسارات تُمرَّر **باسم المسار** لا باستيراد صنف مورد من موديول آخر
(`route('filament.admin.resources.sessions.index')`)، حفاظًا على حدود
الموديولات في البند 2.

### اكتشاف أثناء التنفيذ

`AdminPanelProvider` يعلن 55 موردًا، **16 منها بلا `getPages()`** — بلا مسارات
ولا سبيل لفتحها. هذا ما كان يُخفي أقسامًا كاملة من الشريط: `NavigationManager`
يُسقط أي عنصر بلا رابط ولا أبناء. وإنشاء الصفحات كشف عطبًا كامنًا في
`BadgeAwardFilamentResource` (استيراد `TextColumn` ناقص) لم يظهر قط لأن
`table()` لم تُنفَّذ أبدًا.

### باقٍ

| البند | سبب التأجيل |
|---|---|
| منح شارة | مكانه الصحيح `BadgeResource` لا `BadgeAwardResource`، ويحتاج منتقي مستخدم |
| تحرير المستحقات المؤجَّلة | `ReleaseDeferredEntriesAction` يأخذ حصة التلافي والمعلم، فمكانه صفحة الحصة لا قائمة القيود |
| دورة التسويات المالية | لا مورد `PayrollAdjustment` أصلًا — يحتاج موردًا كاملًا لا زرًّا |
| تصحيح لوحة الطالب | يحتاج تحديد شكل التصحيح المسموح |
| زر الجدولة من المجموعة | المرحلة 4 |

### مستبعَد عمدًا

**تنظيف سجل التدقيق من اللوحة.** `PruneExpiredEntriesAction` موجود بلا زر، وهذا
صحيح: البند 7 يجعل `audit_log` دفترًا append-only، وزرُّ حذفٍ فيه يناقض الغرض
الذي وُجد من أجله. مكانه الجدولة الدورية وحدها.
