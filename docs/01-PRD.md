# 01 — وثيقة المتطلبات (PRD)

**المنتج:** E-School — منصة إدارة مدرسة أونلاين
**النسخة:** 1.0 — أساس المرحلة الأولى
**الحالة:** معتمدة بناءً على [`client-answers.md`](client-answers.md)

---

## 1. المشكلة

مؤسسة تعليمية إلكترونية تدير اليوم نحو **200 طالب** و**16 معلمًا** عبر أدوات
متفرقة: الجداول في ملفات، الحصص على منصة اجتماعات عامة، الحضور في أوراق،
التسجيلات على درايف وأجهزة شخصية، وحساب مستحقات المعلمين يدويًا آخر كل شهر.

هذا يعمل عند 200 طالب. **لن يعمل عند 600، ولن يكون ممكنًا عند 2000.**

النقاط التي تنكسر أولًا:

1. **الجدولة** — تعارض مواعيد المعلمين يُكتشف بعد وقوعه.
2. **المستحقات** — احتساب يدوي شهري يعتمد على ذاكرة من حضر ومن غاب.
3. **الانضباط** — قاعدة "ثلاث غيابات" تُطبَّق بالتقدير لا بالنظام.
4. **المتابعة** — ولي الأمر لا يملك نافذة على مستوى ابنه.
5. **الأثر** — لا سجل يجيب: من غيّر هذا؟ ومتى؟ ولماذا؟

---

## 2. ما نبنيه

**نظام تشغيل للمدرسة الإلكترونية** — لا مجرد LMS ولا مجرد أداة اجتماعات:

- يعرف **من** يدرس **ماذا** مع **من** و**متى**.
- يفتح الفصل المباشر ويغلقه ويسجّله ويؤرشفه.
- يرصد الحضور آليًا ويؤكده المعلم.
- يطبّق قواعد الانضباط بلا تدخل بشري.
- يبني مستحقات المعلمين حصةً بحصة في دفتر أستاذ لا يُعدَّل.
- يُخطر الطالب وولي الأمر بلغتهم وفي وقتهم.
- يجيب على كل سؤال إداري بتقرير مُصفّى وقابل للتصدير.

## 3. المستخدمون

| الدور | من هو | ما يفعله يوميًا |
|-------|-------|-----------------|
| **مدير المنصة** | الإدارة العليا | يرى كل شيء، يعتمد المالي، يضبط السياسات |
| **مشرف أكاديمي** | يتابع المعلمين والمستوى | يراجع التقارير، يعتمد التقييمات، يبتّ في فك التجميد |
| **مشرف مالي** | صلاحية أعلى في المال | يعتمد المكافآت والخصومات وفترة المستحقات |
| **مسؤول تسجيل** | يقيّد الطلاب | يفتح القيود، يضبط المجموعات والمواعيد |
| **مسؤول تواصل** | يتابع الرسائل | يرد على الوارد، يرسل الإعلانات |
| **معلم** | 16 اليوم | يعطي الحصص، يرصد الحضور، يكتب التقرير، يصحح الواجبات |
| **طالب** | 200 اليوم → 2000 | يحضر، يسلّم، يطلب تأجيلًا، يراسل |
| **ولي أمر** | لأكثر من نصف الطلاب | يتابع أبناءه ويتواصل مع الإدارة |

## 4. الأحجام المستهدفة

| المقياس | اليوم | نهاية السنة | العام القادم |
|---------|-------|-------------|--------------|
| الطلاب | 200 | 600 | 1500 – 2000 |
| المعلمون | 16 | ~40 | ~100 |
| الحصص المتزامنة | 5 | 15 | 30 |
| الحصص شهريًا | ~800 | ~2400 | ~8000 |
| تخزين التسجيلات (30 يومًا) | ~0.4 TB | ~1.2 TB | ~4 TB |

**قرار السعة:** كل قرار معماري في هذه الوثيقة مُقاس على عمود **العام القادم**،
لا على عمود اليوم.

## 5. رحلات المستخدم الأساسية

### 5.1 حصة عادية

```
قبل 24 ساعة   تذكير للطالب وولي الأمر والمعلم
قبل 20 دقيقة  النظام ينشئ الفصل عند المزوّد ويفتحه للمعلم
قبل 10 دقائق  زر "دخول الحصة" يصبح فعّالًا للطالب
الموعد        الحصة تبدأ · التسجيل يعمل تلقائيًا · إشعار تسجيل ظاهر
النهاية       النظام يغلق الفصل ويحسب دقائق كل مشارك
+30 دقيقة     الحصة تنتقل إلى "تنتظر المراجعة"
خلال 24 ساعة  المعلم يعتمد الحضور ويكتب تقرير الحصة
الاعتماد      الحصة تُقفل ← تُنشأ قيدة المستحقات ← يُحدَّث سجل الانضباط
```

### 5.2 طلب تأجيل

```
الطالب (قبل الموعد بربع ساعة على الأقل) يطلب التأجيل ويقترح موعدًا
        ↓ إشعار فوري
المعلم + الإدارة
        ↓
المعلم يؤكد أو يرشّح موعدًا آخر → الطالب يوافق
        ↓
تُنشأ حصة تلافي مرتبطة · الحصة الأصلية تصبح "مؤجَّلة"
        ↓
مستحق المعلم عن الحصة الأصلية يبقى مؤجَّلًا حتى تُقام حصة التلافي
```

### 5.3 التجميد التلقائي

```
غياب بدون عذر (1) → رسالة تنبيه للطالب وولي الأمر
غياب بدون عذر (2) → تنبيه + تحذير صريح بالتجميد التالي
غياب بدون عذر (3) → تجميد آلي · وصول الكورسات يتوقف · الحساب باقٍ
        ↓
الطالب يطلب فك التجميد → اختبار جدية من الفريق الإداري
        ↓
اجتاز → القيد يعود نشطًا      لم يجتز → يبقى مجمّدًا (3 محاولات بحد أقصى)
```

### 5.4 إقفال شهر المستحقات

```
كل حصة مُقفلة أنشأت قيدة بالسعر السائد وقتها
        ↓
اليوم 1 + 3 أيام سماح (لالتقاط حصص التلافي)
        ↓
احتساب → مراجعة المشرف → إدراج مكافآت وخصومات بملحوظة
        ↓
اعتماد من مشرف بصلاحية أعلى (غير من اقترح)
        ↓
صرف → إقفال · لا تعديل بعدها إلا بقيدة تسوية في الشهر التالي
```

## 6. متطلبات وظيفية — المرحلة الأولى

### إلزامية للإطلاق

| المجال | المطلوب |
|--------|---------|
| الهوية | حسابات منفصلة للطالب وولي الأمر · تحقق بريد · تحقق ثنائي للإدارة |
| الصلاحيات | أدوار مركّبة وصلاحيات دقيقة — لا شرط على اسم الدور في الكود |
| الطلاب | ملف كامل + خط زمني لكل ما جرى له |
| أولياء الأمور | حساب مرتبط بعدة أبناء مع تبديل السياق |
| الطاقم | عقود المعلمين وأسعارهم وإتاحتهم وإجازاتهم |
| البرامج | برامج ومستويات ومواد · برنامج قد يخدم أكثر من مجموعة |
| المجموعات | حتى 25 طالبًا · أكثر من معلم لأكثر من مادة |
| القيد | دورة حياة كاملة مع سجل الانتقالات |
| الجدولة | تكرار RRULE · كشف تعارضات قبل الحفظ · إتاحة المعلم · إجازات |
| الحصص | آلة حالات كاملة · تأجيل وحصص تلافي · معلم بديل |
| الحضور | ثماني حالات · احتساب آلي + اعتماد المعلم |
| الفصل المباشر | BigBlueButton خلف واجهة مزوّد · نافذة دخول · أدوار |
| التسجيلات | تلقائية · احتفاظ 30 يومًا · أرشفة · روابط موقّعة · سجل مشاهدة |
| الواجبات | إسناد · تسليم · تأخير · تصحيح · تغذية راجعة |
| الاختبارات | بنك أسئلة · اختبارات · درجات · **واختبار فك التجميد** |
| التقارير الأكاديمية | تقرير حصة إلزامي · تقرير شهري مسوّدة يعتمده المشرف |
| الانضباط | محرّك قواعد مضبوط من الإعدادات · تجميد آلي · مسار فك التجميد |
| المراسلات | رسائل داخلية تحت إشراف الإدارة · حائط للصف |
| الإشعارات | محرّك واحد · Outbox · أربع قنوات · لغة ووقت المستلم |
| المستحقات | دفتر أستاذ · مصفوفة النتائج · بديل · راتب · اعتماد بمرحلتين |
| التقارير | لوحات + مُصفّيات + تصدير |
| التدقيق | كل تغيير حسّاس بسببه ومن قام به |
| الاستيراد | Excel للطلاب والمعلمين والمجموعات والمواعيد |
| اللغة | عربي RTL + إنجليزي + فرنسي |

### مبنية ومطفأة

- **فوترة الطلاب** — الجداول موجودة، الميزة خلف `features.student_billing`.
- **صرف مستحقات المعلمين إلكترونيًا** — خلف `features.teacher_payouts`.
- **الشهادات التلقائية** — تحتاج الدورات المسجَّلة، غير المتاحة الآن.

## 7. متطلبات غير وظيفية

| المتطلب | الهدف |
|---------|-------|
| زمن استجابة الصفحة | أقل من 400 مللي ثانية للنسبة 95 |
| فتح الفصل | جاهز قبل الموعد بـ 20 دقيقة، لا عند ضغط الطالب |

| المتصفحات | آخر إصدارين من Chrome و Safari و Edge و Firefox |
| الأجهزة | ويب متجاوب — لا تطبيق أصلي في المرحلة الأولى |
| الخصوصية | بيانات القُصّر بحد أدنى · موافقة تسجيل صريحة · روابط موقّعة |

## 8. مقاييس النجاح

| المقياس | خط الأساس | الهدف بعد 3 أشهر |
|---------|-----------|-------------------|
| زمن إقفال مستحقات الشهر | أيام | أقل من ساعة |
